# 双障碍协议室：具体玩法候选（2026-11-11）

> 用户已于 2026-11-11 选择“玩家和 Agent 各处理一处障碍”作为下一轮玩法基底。本文件是该基底的纸面规则，数值、手感和 Agent 策略价值仍待验证；不是正式预赛方案。保留单屏 2D 横版、玩家手操、玩家侧 Agent、受限世界 Agent、RESET；决赛原型目标为 72 小时开发和约 10 分钟体验。

## 一句话玩法

玩家与自己的 Agent 各有一次解决障碍的机会：玩家用一次强化动作亲自越过一个障碍；Agent 在出发前写一条自动干预规则，让世界在满足条件时消除另一个障碍。第一次通关后世界 Agent 调整障碍并 RESET；位置指令可能失效，针对障碍性质的策略则可能继续有效。

## 关卡与对象

```text
起点 ── 障碍位 1 ── 安全台 ── 障碍位 2 ── 出口
         J 或 D                   J 或 D
```

- `J`：缺口。玩家可以消耗自己的唯一强化动作「跃迁」跨过；若 Agent 的干预在此触发，会生成踏板，直到玩家通过或 RESET。
- `D`：短时闸门。玩家可以消耗自己的唯一强化动作「冲刺」穿过；若 Agent 的干预在此触发，闸门常开，直到玩家通过或 RESET。
- 一轮恰有两个障碍，初始为 `J,D`。两个障碍相隔安全台，玩家有足够时间辨认。玩家的强化动作与 Agent 的干预各只有一次；两个障碍都必须解决。玩家可以在起点、失败后或安全台主动 RESET。

## 操作与信息边界

1. **玩家**看见当前障碍的位置和外观，可移动、用一次「跃迁或冲刺」、决定出发和主动 RESET。玩家不能调用干预接口；如果不让 Agent 部署规则，两个障碍中至多过一个。
2. **玩家侧 Agent**可读前几轮的结构化日志（障碍种类、玩家用了哪个动作、干预何时触发、死亡原因）和干预规则说明；它不能读取当前画面的障碍顺序。玩家可用自然语言描述现场、自己更擅长的动作，以及希望由谁处理哪个障碍。
3. Agent 可提出一条**持续登记的自动规则**，由玩家审核后调用接口部署：`遇到第一个障碍时干预`、`遇到 J 时干预`、`遇到 D 时干预`。出发后这条规则在首次匹配时自动消耗本轮唯一干预次数；玩家无需暂停游戏发指令。可在起点修订或暂停，出发后本轮不可改。
4. **世界 Agent**只在玩家第一次到达出口后的 RESET，从合法变更中选择一种：交换 `J,D` 的先后；或者把两处都改成玩家**刚刚亲自越过的障碍类型**，得到 `J,J` 或 `D,D`。它看得到玩家已公开的动作和干预结果，不读私人对话；变更后在起点显示。这样不会突然要求玩家使用一项尚未成功展示的动作。游戏程序保证两个障碍始终能用“一次玩家动作 + 一次 Agent 干预”通过。死亡 RESET 不改图。
5. **胜利**需要两次抵达出口；第一次取得跨轮保留的证明并强制 RESET，第二次结束。已登记规则跨 RESET 保留，玩家动作和 Agent 干预次数每轮恢复。

## 纸面试玩 A：有效的分工与可迁移策略

| 时刻 | 玩家、Agent 与世界动作 | 结果 |
| --- | --- | --- |
| 初始 `J,D` | 玩家说“跳缺口我比较稳，冲刺容易失误”；Agent 提议 `遇到 D 时干预`。玩家确认。 | 玩家跃迁通过 `J`，规则在 `D` 自动开闸，第一次到出口。 |
| RESET | 世界 Agent 交换顺序为 `D,J`，玩家在起点看到闸门移到了前面。 | 登记的规则仍是 `遇到 D 时干预`，没有因为位置改变失效。 |
| 第二轮 | 玩家让 Agent 解释为什么旧规则仍有效，随后出发。 | Agent 先自动开 `D`，玩家在后面的 `J` 亲自跃迁，第二次到出口获胜。 |

这里的 Agent 策略价值是**把“我负责自己擅长的动作”抽象成跨 RESET 的事件规则**；玩家仍须实际完成自己的障碍。RESET 奖励可迁移的规则，而非强迫每轮都重新聊天。

## 纸面试玩 B：过度委托的具体代价

| 时刻 | 玩家、Agent 与世界动作 | 结果 |
| --- | --- | --- |
| 初始 `J,D` | 玩家只说“前面有危险就帮我处理”，批准 `遇到第一个障碍时干预`。 | Agent 消除 `J`，玩家必须冲刺通过 `D`。若玩家不擅长冲刺，可能失败；失败日志能帮助 Agent 追问偏好。 |
| 玩家勉强完成第一轮，RESET 为 `D,J` | 旧规则仍登记，自动消除第一个障碍 `D`。 | 玩家此轮只需跃迁通过 `J`，可能成功；**不能声称此处必然失败**。 |
| 若世界将初始 `J,D` 改为 `D,D` | 玩家上一轮亲自冲刺通过 `D`，所以这项变更合法。旧规则消除第一个 `D`；玩家仍需冲刺第二个 `D`。 | 若玩家只能勉强完成冲刺，仍有失败风险；但也可能成功，不能宣称宽泛委托必败。 |

**结论**：不能把“用 Agent 太多”设计成机械惩罚。这个候选中，真正可检验的是：宽泛规则会把唯一干预次数花在先出现的障碍，不考虑玩家实际擅长哪一种动作；精确规则会把干预留给玩家难以处理的障碍。是否产生足够明显的体验差异，需要真人试玩，不能在方案里承诺必然失败。

## 纸面试玩 C：旧策略在一种 RESET 下确实失效

初始 `J,D`，玩家亲自跃迁 `J`，Agent 使用 `遇到 D 时干预`，第一次通关。世界 Agent 在 RESET 后合法改为 `J,J`：它针对玩家刚证明会跳的动作加深考验，没有引入玩家不会的动作。玩家在场景里看到两个缺口；Agent 只掌握上轮日志，不知道这次的改图。若玩家直接沿用旧规则，两个 `J` 都不会触发干预，玩家只能跃迁一次，第二个缺口失败。玩家回到起点，告诉 Agent“现在是两个缺口”；Agent 把规则修订为 `遇到 J 时干预`，玩家亲自跃迁另一个，第二次通关。

这条失败链不要求 Agent 故意犯错：旧规则对原来的 `J,D` 完全正确，只是当前画面不在它的读取权限里。RESET 后，玩家是否向 Agent 报告变化决定了两人的计划能否更新。世界选择交换顺序时，旧规则能继续生效；选择复制玩家已处理的障碍时，旧规则需要修订，因此世界编辑的两种结果有不同的策略意义。

## 穷举可解性

| 世界配置 | 可行分工之一 |
| --- | --- |
| `J,D` | Agent 处理 `D`，玩家跃迁 `J`；或相反。 |
| `D,J` | Agent 处理 `D`，玩家跃迁 `J`；或相反。 |
| `J,J` | Agent 处理一次 `J`，玩家跃迁另一次 `J`。 |
| `D,D` | Agent 处理一次 `D`，玩家冲刺另一次 `D`。 |

当两个障碍同型时，`遇到 J/D 时干预`会在首个同型障碍触发；玩家在第二个使用强化动作。失败后回起点仍可修订规则，所以不存在必须重开整个 Demo 的软锁。

### 三条规则的完整结果表

下表写的是 **Agent 已处理其中一个障碍后，玩家必须亲自完成哪一类动作**；`失败`表示 Agent 规则根本不会触发，玩家的一次动作不足以越过两处。

| 关卡 | 干预第一个 | 干预 `J` | 干预 `D` |
| --- | --- | --- | --- |
| `J,D` | 玩家冲刺 `D` | 玩家冲刺 `D` | 玩家跃迁 `J` |
| `D,J` | 玩家跃迁 `J` | 玩家冲刺 `D` | 玩家跃迁 `J` |
| `J,J` | 玩家跃迁 `J` | 玩家跃迁 `J` | 失败 |
| `D,D` | 玩家冲刺 `D` | 失败 | 玩家冲刺 `D` |

因此规则有真实取舍：`干预第一个`面对任何世界配置都能触发，但在初始 `J,D` 迫使玩家亲自冲刺；`干预 D`允许不擅长冲刺的玩家在初始关卡亲自跳跃，却可能在世界复制 `J` 后失效。Agent 可以基于玩家偏好提出取舍，RESET 后玩家需要根据现场判断旧规则还能不能用。这比“选一个保护格子”多了一层可解释的策略，但规则总数依旧很少，仍须与简单菜单作试玩比较。

## 72 小时边界与待验证问题

Godot 原型只需一屏、两个障碍位、`J/D` 两种障碍预制件、一个玩家强化动作计数、一个 Agent 干预计数、三种合法条件、一次世界改图、RESET 与结束状态。Agent 只在对话和提交规则时调用模型；实时触发由游戏程序确定性执行。世界 Agent 只从三种合法改图中选，不自由生成关卡。干预持续到玩家通过，避免把网络延迟或两秒倒计时变成隐藏难度。

10 分钟体验预算：理解双资源与障碍约 1–2 分钟；对话并提交首次规则约 1–2 分钟；首轮手操与第一次成功约 1 分钟；RESET 观察与策略讨论约 1–2 分钟；第二轮手操、可能的一次失败修订和结束反馈约 2–3 分钟。若试玩者直接解出，实际体验可能短于 10 分钟；应以试玩测量，不用强制等待或冗长对白凑时长。

这版比「协定室」更能检验**规则能否跨 RESET 泛化**，且世界的两种编辑会造成“旧策略仍有效／旧策略失效”两种结果。但仍有两个核心疑问：三种规则能否被简单菜单完全替代；玩家的“一次强化动作”是否自然、有趣。若两项都答不上来，应换玩法基底，而不是增加对白或剧情解释。

## AI 必要性审计（2026-11-11）

把所有对话删掉，给玩家一个三选一菜单：`第一个`、`J`、`D`。菜单提交相同的规则后，上面的每一行状态转移、成功与失败都会完全一致。因此这一版**只证明 Agent 专属接口在规则上必要，没有证明生成式 Agent 在体验上必要**。世界 Agent 的选择同样只有两种合法结果；固定脚本也能复现纸面推演。单靠“会解释选择”或“会说话”无法解决这个问题。

如果团队认可“双资源、两处障碍、RESET 后复查分工”的手感，可保留它作为最小关卡白盒，再测试 Agent 是否能从玩家自然语言中的操作偏好、失败日志和新画面描述提出一条玩家未明确指定的策略，并在 RESET 后指出自己的旧规则何时失效。测试时应和三按钮菜单对照：若玩家的决策、理解和成败没有实质差别，就不要把 Agent 规划写成正式方案的主要创新点。若团队不喜欢一次强化动作的资源限制，应直接换关卡核心，不在这套资源规则上继续加功能。
