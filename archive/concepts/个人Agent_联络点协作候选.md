# 个人 Agent：联络点协作候选

日期：2026-11-14。状态：助手提出的讨论候选，**用户尚未确认具体权限**。已确认机制见[侦测定位机制基准](../../侦测定位_机制草案.md)。

时制更新：用户已确认实时行动与持续感知、周期批量上报。下文旧例中按“采样序号”安排动作的表述需要随权限讨论重做，不代表设备只在上报瞬间检测。具体权限、计划执行方式及现场／设备侧的信息分工均未确认。

### 最新纠正：现场可视性与助手价值

用户指出：灯覆盖的格子、摄像头扫描范围和机器人位置应当在游戏画面中清楚表达。不得为制造信息互补而隐藏这些基础反馈。个人 Agent 可以读取同一份场景数据用于规划，但复述这些数据不能作为其核心价值。

下文“读取局部调度＋上传照明计划”保留为此前候选，尚未解决相对直接操作界面的价值。个人 Agent 的招牌操作需要继续讨论；“干预后续传感报告，让系统获得误导线索”是新候选，尚未确认，不改变现行真实采样、历史不可回写与定位规则。

### 对“欺骗计划”的进一步质疑

用户指出两个问题：若助手掌握信息并独立选择最有利的编辑，玩家可能没有参与决策的必要；同时，不应假定助手能够可靠预测系统 Agent 的推断并计算最优欺骗方案。

据此撤回“最大化系统误判概率”作为个人 Agent 的能力承诺。报告干预本身仍可讨论，但其合法效果必须由程序规则明确；助手生成方案与程序检查合法性、时序应分开。能读取报告不等于已知对手决策函数或存在可计算的误判概率。

“将一条未来报告延迟到下个周期交付，保留原观察时间戳”仅作为效果明确的讨论例子，尚未采纳；即便采用，也不能改变统一上报窗口计数或推迟系统定位。它不自动解决对话价值、AI必要性或过度依赖代价。路线意图可以成为协商输入，但不能仅凭玩家说出路线就声称已形成有意义的合作。

## 1. 已有前提

同层方格、连续实时移动；灯有同时关闭数量、持续和冷却限制；摄像头和机器人持续感知、周期上报，系统每N个上报批次定位一次，推理期间暂停。系统在周期边界决定下一周期巡逻和摄像头调度。个人 Agent 仅在联络点接入，联络对话期间也暂停游戏。用户提出限制轮数与内容量，具体额度未定；最新候选约束见机制基准第2.4节。

## 2. 能力建议

个人 Agent 是接入局部维护网络的规划搭档。玩家在联络点说明目标与现场情况；助手读取本地设备配置、与玩家协商路线，再上传一份短期照明干预计划。玩家离开后，游戏执行已批准计划，不能随时追加命令。

执行器只按采样序号与灯编号执行有限合法动作，没有新增自主装置智能、不运行任意脚本。是否采用计划机制、是否允许离点后执行，均未确认。

## 3. 灯的归属提案

- 系统维护基础状态：灯默认开启、到期自动恢复。先不要求系统每周期主动安排关灯；没有耗电或其他约束时，全亮通常最利于侦测，额外调度未必产生选择。
- 个人 Agent 拥有联络点覆盖范围内的临时关灯权限，服从已有数量、时长与冷却约束。
- 已批准的合法干预在执行窗口内不会被系统立即撤销，到期按规则恢复。否则容易出现双方反复覆盖同一状态。
- 摄像头正常调度与巡逻归系统；第一版候选不额外增加助手改摄像头、遥控机器人或篡改观测报告的能力。

以上均为建议，不是已确认的控制分工。

## 4. 读写边界候选

| 类型 | 建议内容 |
| --- | --- |
| 读取 | 本联络点覆盖的灯编号、坐标、照明格集合、剩余冷却 |
| 读取 | 已生效的本周期局部摄像头调度、巡逻范围；不包含未决定的未来调度 |
| 读取 | 已获授权的历史执行及失败记录 |
| 写入 | 按采样序号安排局部灯暂时关闭，向玩家预览时刻和影响格子 |

是否提供实时场景图、机器人实际位置仍待确认。玩家说明自己的目标、位置与现场观察；不能为了制造对话，假装双方已获得的信息不可读取。

调度读取发生在本周期配置应用后。系统可在周期结束后重新调度，助手不能把当前配置当作下一周期的保证。

## 5. 能力示例

只演示一种计划，不锁定地图尺寸、N、移动速度、关灯和冷却数值：

- 联络点在(2,3)，玩家计划经过A区（x=3–4，y=3）、B区（x=5–6，y=3）。
- 助手读取局部生效配置与灯冷却，和玩家确认路线。
- 候选计划：第二次采样前短暂关闭A灯；A恢复后，第三次采样前短暂关闭B灯。
- 游戏验证数量、时长、冷却和可作用区域，再由玩家预览批准。
- 玩家离开联络点，亲自执行路线；已批准计划按采样编号执行。

这些窗口是否覆盖真实移动距离、能否屏蔽对应传感器，需要验证，不能仅凭示例就声称安全或可通关。

## 6. 联络点与外部 Agent

可落实的约束是游戏数据与接口权限：角色位于联络点时允许读取和提交计划；离开后不接受新命令、不再推送实时情报。玩家现实中仍可能与自有 Agent 聊天，游戏内通信入口应通过接口权限体现。

联络对话期间暂停游戏已确认：在联络点开始会话时冻结机器人、摄像头、灯和所有游戏计时，结束会话即从冻结状态恢复，不要求先离点。没有有效修改时，装置接续原轨迹；存在获准且此时生效的修改时，从冻结状态接续新安排，不补算暂停时间。个人 Agent 能改哪些对象、改动的生效时刻，以及是否采用离点后执行的预设计划仍待讨论；不能把系统 Agent 的常规周期调度规则直接当成个人 Agent 的权限结论。通信额度、能否反复修改、权限何时释放仍待讨论。

## 7. 价值与未解决问题

希望让对话围绕路线、时序和受限设备组合展开，助手产出可执行计划。是否比直接按按钮更有趣、是否体现生成式 Agent 的价值，未验证。

联络点与计划时效限制持续代打，但不自动解决过度依赖助手的代价。不能故意让助手提供错误建议，也不能把玩家走慢简单当作此目标已实现。
