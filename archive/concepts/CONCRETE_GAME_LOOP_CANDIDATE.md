# 单屏分岔室：第一版具体玩法候选（2026-11-11）

> 历史候选：纸面检查发现，助手在这里主要是选择保护位置，过于接近“专属按钮”。目前更优先讨论 `CONTRACT_ROOM_CANDIDATE.md` 中的能力协定模型；本文件保留作比较，不作为当前基准。

## 一句话玩法

玩家在五步以内从起点到出口。两条路线都至少有一处致命危险；玩家侧 Agent 每轮只能为**一处危险**设定一次自动保护。第一次到达出口会触发 RESET；世界 Agent 看见玩家刚走的路线后，改变下一轮的危险布置。第二次到达出口才获胜。

## 关卡白盒

```text
              上路： U1 ── U2 ── U3      （起点到出口 4 步）
            ╱                        ╲
起点 S ────                          ──── 出口 G
            ╲                        ╱
              下路： D1 ── D2 ── D3 ── D4 （起点到出口 5 步）
```

一个节点对应一次移动；玩家可以在起点选择上路或下路，中途不能换路。每轮有 5 次移动。初始致命格为 U2 和 D3，均以现场征兆标示；其位置和效果对玩家可见。路线长度不同，是时间预算上的最小取舍；危险变化会决定哪条路线可行。后续视觉可做成单屏横版通道，不必是文字图。

## 精确规则

1. 玩家行动：在分岔点选一路，然后每次前进一步；走到致命格会失败并 RESET。行动预算用完、尚未到出口也 RESET。
2. 玩家侧 Agent：每轮有**一次保护**，可提交一个触发位置（U1–U3 或 D1–D4）。当玩家进入该位置时，若该格致命，本次伤害被抵消；若不致命，保护仍被消耗。玩家不能直接调用这个接口。
3. 保护设置可跨 RESET 保留，但每轮保护次数恢复为一次。玩家可在下一轮开始前通过对话让 Agent 改位置或停用；Agent 只能看到之前的结构化行动日志，不能直接看到 RESET 后的新地图。
4. 第一次到出口时，进度记为 1，并**强制 RESET**。第二次到出口时获胜。进度跨 RESET 保留。
5. 世界 Agent 在每次 RESET 后，只能从两种合法动作中选一种：**给上一轮走过的路线增加一处致命格**，或**移动该路线内的一处致命格**。它看得到路线和保护实际触发的位置，看不到玩家与私人 Agent 的对话。变更在玩家行动前展示；地图必须至少保留一条只需一次保护就能穿越的路线。
6. 世界 Agent 不得在玩家行进途中临时修改格子，也不得改行动预算、保护次数或胜利条件。游戏程序检查所有地图变更的合法性。

## 一个完整推演

| 时刻 | 状态与选择 | 结果 |
| --- | --- | --- |
| 第一轮 | U2 和 D3 致命。玩家告诉助手想走较短的上路；助手将一次保护设置在 U2。玩家走 S→U1→U2→U3→G。 | 4 步到出口；进度变为 1，强制 RESET。保护 U2 的使用留下公开记录。 |
| RESET | 世界 Agent 观察到玩家走上路并使用 U2 保护，给上路 U3 增加一处致命格；下路仍只有 D3 致命。玩家在场景里看得到 U3 的新警示。 | 上路现在有 U2、U3 两处危险，一次保护无法通过；下路 5 步、只需保护 D3，仍可通过。 |
| 盲目沿用 | 玩家不检查场景，也不把变化告诉助手；保护继续设在 U2，并再走上路。 | U2 的伤害被抵消，但在 U3 失败。失败原因与新危险位置明确可见。 |
| 合作修订 | 玩家告诉助手“上路多了 U3，下路 D3 仍亮着”；助手对照历史，提出改走下路、把保护改到 D3。玩家确认并亲自走 S→D1→D2→D3→D4→G。 | 恰好 5 步到出口，进度 1→2，获胜。 |

## 这版回答了什么，没回答什么

- **RESET 有玩法作用**：第一次成功不直接结束；世界根据公开行动改变配置，旧保护设置跨轮保留，玩家必须重新选择路线和保护目标。
- **玩家侧 Agent 在规则上必要**：所有可在预算内通过的路线都有致命格，只有它能提交一次保护；玩家独自行动无法通关。
- **过度委托的代价有明确因果**：保护是自动、持续的委托；世界看见其公开使用并改变布局。玩家若把原策略当成无须复核的承诺，第二轮会在新危险上失败。使用助手本身不扣分。
- **尚未证明 AI 在体验上必要**：这版地图很小。玩家也可能自己看图后直接命令助手“保护 D3”，此时助手仍像专属按钮。要验证 AI 价值，需要测试它是否会基于玩家的自然语言偏好、日志和新描述主动提问、提出并修订策略；若固定菜单效果相同，就要换设计，不能只给按钮加对白。
- **尚未证明世界 Agent 在体验上必要**：仅一种固定反制时可由脚本替代。原型可以保留“增加”与“移动”两个合法变化，让世界 Agent根据玩家行动选择，但应比较它和固定脚本的体验差别。

## 72 小时内的最小演示边界

一张单屏白盒图；两条路线；一次保护接口；进度 0/1/2；世界 Agent 两种合法变更；最多三次明显的重启反馈；玩家侧 Agent 内置演示入口与同权限的外部 skill 接口。模型只在 RESET/对话/提交保护时调用；移动、危险结算、胜利判定由 Godot 处理。按照 10 分钟演示预算安排：约 1 分钟理解规则，2 分钟讨论并完成第一轮，1 分钟观看 RESET 反馈，3 分钟讨论与尝试第二轮，剩余约 3 分钟留给一次失败后的修订和结尾。实际时长必须通过纸面试玩或低保真原型测量，不能当作既成结果。

## 决定是否保留这套底座的验证问题

1. 玩家是否能在 30 秒内看懂路线、保护和两次到出口的规则？
2. 第二轮出现新增危险时，玩家是否自然想到向助手报告变化并重订计划？
3. 上下路线是否提供有意思的取舍，还是只是“数危险点选唯一正确路线”？
4. 助手的对话规划是否真的增加决策价值，还是固定菜单就足够？

若第 3、4 项回答是否定的，应保留 RESET、受限世界变更与一次保护这三个可测结构，重新设计关卡内容或 Agent 专属能力。
