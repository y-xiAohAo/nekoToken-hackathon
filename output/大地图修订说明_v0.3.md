# 《请本人到场》地图修订：从单室改为分区检查区

2026-11-14。用户提出原图空间太小，系统容易定位，要求扩大地图。以下是据此画出的候选布局，尚未试玩；尺寸与设备数量用于本版示意。

## 地图怎么改

- 候选外框 36×24 格，所有可走位置同层。取消“单屏房间”限制；实机拟随角色平移视角，方案图展示全貌。
- 两道带开口的隔墙分出西南入场区、西北分流区、东南维修区、东北撤离区。四区之间形成环路，不做必须按顺序走完的四个关卡。
- 分区之间的通口宽 3 格，区内再放少量遮挡块。玩家可以从不同方向接近维修区，也能在维修后选择直接撤离或绕回另一侧。
- 示意放置 3 个联络点、1 台电机、4 台摄像头、6 盏灯、2 台巡逻机器人。沿用已有装置，不增加新的机关类型。
- 保留已有照明、上报、周期定位、命令覆盖和双重 RESET 规则。

## 面积变大为什么还不够

系统猜的是当前位置。地图再大，如果最后一条可靠目击刚发生，或全图都被连续可靠观察，系统仍可能猜中。需要一起看以下几件事：

1. 一次定位能覆盖多大范围。扩大地图时不按比例扩大定位范围；本图只用 5×5 格方框示意，正式形状和大小仍待定。
2. 最近一次可靠观察后，玩家来不来得及走到不同位置。用格数算移动距离，并与定位节奏一起调整。
3. 这些去向是否被新报告排除。遮挡和照明不足产生“无法确定”，不能算“无人”；有新鲜可靠报告时，系统可以缩小候选范围。
4. 一条路线是否在唯一出口重新汇合。分叉之后应留出实际行动空间，不能画出两条线却马上回到同一个狭口。
5. 任务事件会透露什么。一台电机的 ID 本身就能指出维修位置；去掉坐标并不能解决这个问题。维修时刻应保留，开始／完成等事件粒度仍待定，不能改报假信息。

示意推演：系统曾在南侧通口附近得到“有人”报告。若之后两条绕行路线均未被可靠观察，且剩余行动时间足够，玩家可以绕遮挡块北侧，也可以绕南侧；到定位时，两处落脚点可能无法被一个固定大小的定位框同时覆盖。此例只说明布局要满足的条件，不代表已经证明可逃脱。若维修事件或后续目击把玩家锁定，系统猜中是合理结果。

## 72 小时内怎么控制规模

只做一张地图，复用地板、墙、灯和摄像头模块。四轮 RESET 复用同一拓扑，改变合法设备配置。增加路线与遮挡，不增加楼层、城市漫游或额外关卡。是否应缩至 32×24 格、设备数量如何取舍，待灰盒验证；36×24 格先作为方案中可讨论的候选。

验证应关注：刚目击与较旧目击的区别；维修驻留是否导致必败；分叉是否真的提供两个可达且未被排除的位置；新增设施后是否仍有可行动路线；含对话和推理等待的完整体验是否接近 10 分钟。目前没有这些试玩数据。
