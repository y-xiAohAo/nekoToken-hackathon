## 2. 这一版画面究竟画什么

- 固定等距俯视，一屏看完整个室内；前墙及部分顶面剖开以便观察。
- 前侧是连续的地面检查通道，后侧是抬高一层的值班台；高台不覆盖主通道。
- 入口在左端，出口在右端。出口隔墙封住所有绕行空间，门 D 是唯一通道。
- 全场只有一名简化玩家与一台双足巡检机器人；后文“守卫”均指机器人。个人 Agent 通过对话与线路接口参与，没有跟随角色。
- 图中只画现有机制所需设备，不添加电梯、机关桥、武器、跳台、激光网或额外NPC。

## 3. 空间关系与可达性

| 区域／设备 | 位置与关系 | 必须看清的用途 |
| --- | --- | --- |
| 入口与玩家 | 左前侧入口缓冲区 | 玩家起点，在摄像头检测区外 |
| 摄像头 C | 入口后的一处窄检查口，朝向必经地面 | 玩家通过时进入检测区；地面扇形标明覆盖范围 |
| 藏身柜 H1 | 通过摄像头后的左侧凹位，地面巡逻区之前 | 可在这里躲藏、观察守卫与楼梯 |
| 主通道 | 从 H1 经巡逻区、H2 到 D | 有一定地面深度，但不能从守卫的完整检测范围外贴边绕过 |
| 守卫 | 初始在主通道中段 | 朝向、视野与地面巡逻路线可辨认 |
| 楼梯 | H1 右方、主通道中段后缘 | 普通可步行楼梯，两端都清晰，没有断层 |
| 值班台与开关 S | 后侧高台，连接楼梯上口 | 守卫熄灯后会到这里按开关；玩家也可以走上来 |
| 走廊灯 L | 主通道上方的墙面支架 | 照亮巡逻区；光源位置清楚、不挡主要画面 |
| 藏身柜 H2 | 巡逻区偏右的侧凹位、门之前 | 玩家可分段推进；柜子不能塞满或堵住通道 |
| 安保门 D | 右端出口隔墙的唯一开口 | 关闭时真实隔断路线；没有绕到门背后的地板 |
| 出口 | 门右侧短缓冲区 | 亲自穿过门并抵达这里才通关 |

必要防误读约束：

- 值班台是通道后侧的死端，不是通往出口的二层捷径。
- 高台边缘有护栏；不能直接跳下、走下或跨到另一平台。
- 无坑洞、无需要跳跃才能抵达的位置。
- 楼梯下口不堵塞主通道；守卫上楼后，玩家确实能从前侧通道通过。
- 图中为了展示而隐藏的前墙，仍是游戏空间边界；不能把剖面画成一条可绕行的外沿。
- 柜子靠墙凹入，门朝可行走区域，角色能正常进出。

## 4. 画面表示一个时刻

主图画“初始状态”：灯亮、门关、玩家在入口、守卫在地面巡逻。不要同时画门已开、守卫已上楼等之后才出现的状态，以免读者误以为有多个守卫或同时发生的事件。

图例把三种信息分开：

1. 实体：玩家、守卫、摄像头、灯、门、柜子、开关、楼梯。
2. 空间：地面巡逻虚线、楼梯上下行路线、摄像头／守卫视野范围。
3. 方案：在独立小图例中表示 C→L、S→D；标“改线方案示例”，不与主图初始状态混为一谈。

主场景至少占画面四分之三，说明文字放在留白处。可在后续标注处理中叠加少量清晰中文；不把生成出的错误文字当成真实设备说明。

## 5. 视觉与操作

- 形式：有体积、材质和高差的2.5D等距关卡剖面，避免横版截面。
- 镜头：固定高位三分之四视角，能同时看清地板、角色正侧面和高台顶面。
- 美术：适合小团队原型的简洁实体块面、可读的人物与设备轮廓，室内材质不过度复杂。
- 阅读优先：两处柜子、摄像头、门和开关要能在缩小预览时辨认；相邻高台不能把主通道挡住。
- 操作：WASD 沿地面移动，楼梯正常步行，E 交互与躲藏，Tab 与助手讨论并暂停。禁用跳跃。
- 实现：此处不锁定Godot 2D投影或3D正交相机。两者都需实现相同空间关系；不能仅为效果图提前扩展自由镜头或复杂3D交互。

## 7. 产出验收

- 首眼能找到入口、玩家、守卫、出口，并看懂地面与高台的关系。
