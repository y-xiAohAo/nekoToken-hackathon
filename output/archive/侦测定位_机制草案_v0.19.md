### 最新决定：实时行动、实时感知、周期上报

用户确认采用实时方案。玩家连续移动；灯、摄像头与机器人在游戏时间中持续运行。设备由游戏程序持续检测，发现玩家可以发生在任意游戏时刻；按固定周期批量上报，并保留实际观察时间戳和当时的检测区域。不采用只在固定上报瞬间检测玩家的规则，不逐帧调用语言模型。

必须区分发现时间、上报时间、定位时间。N 统计固定上报批次，不统计发现事件数量或设备报告条数；没有发现事件也不自动等于可靠确认“无人”。系统仍在周期定位时暂停游戏，按冻结位置结算。用户进一步确认联络点对话也暂停游戏，并提出限制轮数及内容量。具体检测频率、上报间隔、N、记录压缩方式、通信额度与个人 Agent 权限继续待定。

用户已确认上一轮简化方案：格子照明只有亮／暗，程序确定性感知，报告保留有人／无人／无法确定，不增加数值亮度或置信度；摄像头固定观察距离、瞬时视野夹角和首版扫描速度，优先调整扫描朝向与区间。具体接口权限、合法范围和生效规则继续细化。用户进一步确认双重RESET设计：系统3次轮间复测形成4轮评估，玩家整场共享3次局部定位周期回退；一轮最终失败后仍进入下一轮、最后总评。玩家、个人Agent和系统Agent在两类RESET后均保留各自获准的记忆，系统RESET不能清除个人助手记忆。具体评分、快照字段和时长仍待细化，详见第6.2节。

## 2. 实时感知、周期上报与定位时序

### 2.1 基本参数

| 符号 | 含义 | 状态 |
| --- | --- | --- |
| Δt | 相邻两次统一上报之间的间隔 | 数值待定；不再表示现场检测间隔 |
| N | 一次定位前累计的上报批次数，正整数 | 数值待定 |
| T | 定位周期，T = N × Δt | 关系已明确 |

设备在行动阶段持续感知，在统一上报时刻交付这一窗口的观察记录。一个窗口可以包含零个、一个或多个发现事件。N 统计统一上报批次，不统计设备报告条数或发现次数；增加设备、发生更多目击都不会自动加快定位，没有目击的窗口同样计数。

记录保留现场事件的原时间戳与当时检测区域。上报时的朝向和机器人位置不能替代观察发生时的状态；后续移动或关灯不反向改变已经发生的观测。

```text
行动期间持续感知 → 上报批次 1 → … → 上报批次 N → 暂停定位一次
恢复行动并持续感知 → 上报批次 N+1 → … → 上报批次 2N → 暂停定位一次
```

每次到达定位节点，先完成截至该时刻的上报批次，再形成系统本次可使用的信息。系统不能拿到这一节点之后的未来观察。随后进入**推理暂停阶段**：游戏时间停止，玩家、机器人、摄像头和灯保持当前状态，停止新增感知事件和上报；系统 Agent 基于截至该时刻的授权报告推理并提交一次定位。判定完成后，未命中才开始下一周期。网络等待会增加现实中的体验时长，但不会消耗游戏内行动时间或积累下一周期的观察。

T = N × Δt 表示一个周期的游戏内行动时长，不包含模型推理等待。按“游戏暂停”的含义，灯关闭剩余时间与冷却同样冻结；网络等待不使冷却恢复或灯自动亮起。

### 2.2 报告包含什么

报告结构候选包含：上报批次与时间、设备标识、观察时刻或区间、当时检测区域，以及有人／无人／无法确定。实际观察时间不被上报时间、模型读取时间或网络返回时间覆盖。同一批次允许保留多个不同时间的状态记录，不能只用上报瞬间的状态替代整段观察。

用户已确认时间戳与三种结果；其余字段是为解释信息来源而提出的记录建议，具体接口结构尚未确定。

新增修复上报是任务交互事件，与下述有人／无人／无法确定的视觉观察报告分开表达，事件粒度待讨论。沿用既定周期批量上报时序，不因多了一条任务事件改变上报批次N的计数或临时追加系统定位；具体候选见第6.3节。

三种结果按以下含义继续细化：

- **有人**：在记录的时刻或区间、检测区域内确认存在玩家，不直接交付真实玩家坐标，也不代表上报时玩家仍在那里。
- **无人**：在记录的时刻或区间，该区域被可靠检查且未发现玩家；不能仅凭本批次没有发现事件就作出此结论。
- **无法确定**：在记录的时刻或区间，照明、遮挡或覆盖不足，不能可靠判断该区域是否有人。

若记录“失去观测”，它只说明设备不再看见玩家；应结合照明和覆盖判断后续属于无人还是无法确定，不能自动推断玩家已经离开。

空间以方格表达。用户进一步明确“有人”对应一片有限区域，不能直接给真实玩家格，也不能把区域做得过大；系统依靠多个设备带时间戳的上报交叉推理。区域具体大小、部分可见格子的编码及“无人／无法确定”的分区方式仍待讨论。摄像头和机器人采用第4.2节的统一可观察条件。旧报告描述历史状态；玩家移动后，旧“无人”不能直接当作当前位置证据。不同时间的“有人”不能直接当作同一时刻求交集，仍需考虑移动。

### 2.3 推理暂停后的结算口径

用户已确认“推理期间游戏暂停，完成推理后进入下一周期”。因此，首版应采用一个明确的快照口径：

1. 第 N 个上报批次完成，记录这一定位边界的玩家坐标、装置状态、机器人位置与截至该时刻的报告。
2. 立即冻结现场；系统 Agent 读取截至该时刻的授权历史。
3. 系统提交一次坐标范围；程序将它与**定位暂停时冻结的玩家坐标**比较。
4. 命中时，玩家可消耗一次剩余局部回退，恢复本周期起点快照；此时不结算本轮失败。放弃或次数用尽则本轮失败，按多轮流程进入下一轮或最终总评。回退不额外插入一次新的系统调度，恢复已保存的本周期配置。
5. 未命中则系统获得新增一处设施的机会，并在暂停期间确定、验证下一周期的既有装置调度。巡逻与摄像头命令在下一周期开始生效；新增设施的具体生效时机、灯光基础调度归属仍待讨论，不默认新增设施立即造成一次额外观测或定位。

这使网络推理耗时不改变玩家可移动距离，也不会出现系统用旧报告而玩家已经在推理期间走远的争议。以下仍需单独定稿：

- 玩家在联络点会话期间冻结系统定位计时；系统推理／结算期间不进入联络，两阶段互斥。助手改动在会话结束后提交；离开后是否执行额外的预定动作尚未确认。
- 模型超时、返回非法范围或服务不可用时，是跳过本次定位、使用固定兜底范围，还是直接重试。
- 未命中后的猜测区域是否向玩家显示；显示会增强可读性，也会提供下一周期的反制信息。

### 2.4 联络对话暂停与通信额度

用户已确认定稿：玩家到达联络点并开始会话时，整个关卡冻结。玩家、机器人、摄像头、灯的当前位置与运动阶段、灯持续时间、冷却、感知与上报计时共同保持不变；对话结束后从会话开始前的游戏时刻继续运行。现实中的阅读、输入和模型等待不使冷却恢复、不产生新观察，也不推进定位倒计时。

会话中可为已获准的对象准备改动；暂停期间装置不实际运动，计时不推进。会话结束后提交通过校验的助手改动，随后恢复行动；没有有效改动的部分沿原安排继续。具体可改字段及是否开放离点后的预定动作尚未定稿。系统仅在定位猜错后的独立暂停阶段调度，不在联络过程中改动设施。

因此，恢复后的轨迹有两种来源：没有有效修改时，装置从冻结位置与运动阶段沿原轨迹继续；存在已获准且此时生效的修改时，从冻结状态接续新安排。会话结束即恢复游戏，不要求先走出联络点；仅经过联络点是否自动发起会话尚未决定。冻结期间不补算移动、感知或冷却时间。

用户已明确：每个联络点在每个完整RESET轮次只能会话一次；一次会话最多提交1–2个改动，多个联络点分别计算。局部回退恢复快照中的使用标记：快照中未使用的点可重新会话，已用的点仍然已用。系统整轮RESET开启新轮，重新开放各点。仍需玩家到达可用联络点，不开放离点后的远程追加命令。具体对话轮数、每条内容量未定。以下候选约束仍未定稿：

- 以“玩家发送一条消息＋助手回复一次”为一轮；草稿修改、工具执行回执和玩家确认计划不计作额外对话轮数。模型失败不扣玩家额度，技术重试另外限制。
- 起测候选为一次联络最多3轮对话，玩家每条约200字、助手每条约200–250字；这些数字未确认、未试玩。在同一当前分支里离点后返回同一点不重新获得会话；其它联络点仍可按各自额度使用。局部回退恢复使用标记的规则不受此限制影响。
- 对话期只读本次授权的数据快照，不推进现场、不获取未来报告；暂存干预供玩家确认，恢复行动时按合法规则应用，避免在暂停期间无限试改真实世界。
- 如果采用计划执行，每次联络只确认一份有限计划；覆盖时长、动作数量、执行后是否还能修改待讨论。离点后能否执行预先计划本身仍未确认，不能据此新增常驻实时读取或追加命令权限。
- 联络与系统推理／结算互斥。联络期间定位计时冻结；系统阶段结束、恢复行动后才可进入联络。不将并发指令仲裁列为当前玩法问题。
- 自有外部 Agent 的现实聊天次数和回复字数不能靠游戏强制限制。游戏内入口可限制消息；外部接入应在游戏接口限制授权数据、有效提交与执行额度。skill中的短答约定不能代替接口权限。

额度用完不直接判负。通信轮数与内容量用于控制会话时长，每次1–2个改动及各点每轮一次用于限制现场干预，两者分别表达。局部回退恢复快照里的联络使用状态和现场配置，保留历史对话，消耗不恢复的全局回退次数；不另立一个回退不返还的干预账本。依赖代价的具体效果仍需演练，见第4.5节。

## 3. 灯的关闭与冷却

照明已确认采用格子亮／暗二值。至少一盏开启且覆盖该格的灯使其为亮；多灯叠加不提高数值亮度，关闭一盏灯后仍可能有其他灯使该格保持亮。具体照明覆盖格如何计算及如何受墙影响继续待定。

已确认三个约束共同存在：

1. 同时处于关闭状态的灯不能超过规定数量。
2. 单次关闭不超过规定时长，到期恢复照明。
3. 关闭操作存在冷却，不能无限连续关闭。

同时关闭数量、持续时长和冷却时长均未定。冷却从关闭时还是恢复照明时开始、提前恢复是否允许及是否改变冷却，也未确定。应保证最终规则确实存在照明恢复窗口，不能通过即时重关等操作绕开。

关灯改变关闭期间能获得的观察，不删除此前已经发生的观测，包括尚未上报的正常记录。报告是否可由个人 Agent 单独干预仍待讨论。玩家移动可以让旧位置情报逐渐过时。

关灯效果按实际游戏时间与持续检测计算。在上报之前才关灯，不能抹掉窗口内更早的目击；灯恢复后，设备可在下一次上报前重新发现玩家。具体如何将这些变化压缩成报告待定。

V3图只明确标注一盏功能灯。将房间划分为2–3个独立照明区是此前规模建议，尚未确认；装饰灯不自动进入可操作清单。

## 4. Agent 权限：已知方向与未定边界

- **玩家**：亲自移动、观察、躲藏，在指定联络点与个人 Agent 协商。
- **个人 Agent**：完全看不到地图分布，依靠玩家描述理解设施代号、位置与覆盖关系；以有限关灯及调整摄像头扫描朝向／区间为当前干预方向。双方按同项有效指令的先后相互覆盖；助手每次会话最多1–2个改动，各联络点每轮一次，使用状态随快照恢复。非空间接口信息、具体可改字段及单个改动的计数边界待定。机器人与上传报告的修改尚未确认。[联络点协作候选](../../archive/concepts/个人Agent_联络点协作候选.md)仍含历史提案，以本文件较新决定为准。
- **系统 Agent**：读取授权感知报告并提交定位；本周期定位猜错后，在暂停结算阶段提交下一周期的设施调度。
- **信息边界**：真实玩家坐标由游戏程序用于命中检查，不直接提供给系统 Agent 作为推断输入。
- **现场可视性**：灯覆盖格子、摄像头当前扫描范围、机器人位置应在玩家画面中清楚表达；个人助手不直接读取这些现场数据，由玩家将所见转述给它。
- **仍需明确**：灯的基础调度归属、个人 Agent 的非空间接口信息、改动计数、巡逻范围如何转为简单路线、固定视野朝向如何随移动变化。

现有规则不包含机器人近身抓获、传感器看见即判负或模型自行宣布命中。

### 4.1 由暂停规则确定和建议的边界

- 已明确：机器人、玩家在推理期间均不移动，一次定位节点只结算一次范围。
- 规则推导：截至定位边界的观察保持不可回写，模型计算期间不获取新的现场观测。
- 已明确：个人 Agent 仅在联络阶段获得改动机会，会话结束后提交；系统推理／结算期间不进入联络，联络期间系统不推理或调度。
- 已明确：系统只在本周期定位猜错后提交下一周期配置，随后恢复行动；行动期装置按已有设置运行。

### 4.2 已确认：二值照明、确定性感知与摄像头参数基准

状态：用户以“同意这套机制”确认上一轮推荐的简单判定与摄像头参数方向。具体数值、报告编码、个人 Agent 接口权限及临时干预执行规则仍待定。

- **照明**：每格只有亮／暗。至少一盏开启且覆盖该格的灯使其为亮；多盏灯叠加不提高数值亮度。关闭一盏灯只移除它的照明贡献，其他灯仍可能使格子保持亮。覆盖格如何受墙影响继续待定。
- **感知**：设备对格子的可观察条件为处于当前视野、无遮挡且格子为亮，由程序确定性判定。摄像头和机器人共用该规则；不引入发现概率、曝光积累或数值置信度。美术光照可渐变，但判定仍依据明确格子状态，暗处也应让玩家看清自己与地形。
- **报告三态继续保留**：指定区域内发现玩家为有人；完整检查指定区域且未发现才为无人；存在未检查部分且未发现为无法确定。报告应区分实际检查区域与完整扫描范围，不能把暗处、遮挡或视野外的未知范围统称无人。具体报告粒度与编码仍待定，不据此开放真实玩家坐标。
- **摄像头参数**：区分单个时刻的视野夹角与摆动覆盖的扫描角度。首版固定观察距离和瞬时视野夹角，优先开放扫描中心朝向与扫描区间；扫描速度先固定，若后续需要再讨论少量合法档位。临时修改的持续时间、合法范围、双方权限和生效时机尚未确认。
- **时序延续**：确定性目击只形成观察记录，不直接判负；周期定位仍按已定规则进行。历史记录不因随后关灯或转向而改变。模型面对的信息不完整与记录过时仍存在，无需通过随机感知制造不确定性。

### 4.3 已确认的信息协作与控制权候选

**已确认**：个人助手没有地图视图，玩家描述是其现场空间信息来源。助手可以保留自己从对话整理的设备关系与旧路线，RESET不清除这些记忆；这些是玩家提供的信息和历史认知，不是接口保证正确的当前全图。玩家需要提供目标、路线意图、设备代号与相关位置关系，并补充现场变化。

当前控制方向与接口建议分列如下；标为建议的细则尚未确认：

- skill只说明可调用操作与合法参数；接口可返回设备代号／类型、剩余额度和执行回执，不顺带提供坐标、覆盖格、实时轨迹、截图或观察报告。具体可读字段需逐项确定；错误信息也不应变相返回全图。
- 助手先依据玩家描述比较有限可行干预，再提出建议或针对缺失信息提问；不把玩家一句“关L2”直接翻译为工具调用当作全部策略价值。它不需要预测敌方模型的心理。
- **用户最新方向：相互覆盖**。同一设施、同一控制项的最后一条有效指令生效，双方没有固定的身份优先级。系统可覆盖助手设置，助手也可覆盖系统设置；助手每次联络会话最多做1–2个改动，系统可以调整更多设施。各联络点每轮各一次，局部回退按快照恢复使用状态。具体取1还是2，以及一次改动如何计数留待原型细化。
- **持续规则**：一条设置保持到后续有效指令修改该项。系统进入下一调度周期但未修改此项时，原设置继续；不再采用“到边界自动撤销助手设置”或“恢复被覆盖的旧系统方案”的建议。另一台设施或同设备的无关控制项收到命令，不自动清除其余设置。
- **硬规则仍生效**：灯关闭达到既定时长后自动恢复，存在冷却和同时关闭数量限制；双方都不能借后发命令绕过。无效指令不改变当前设置。RESET按已定规则恢复现场，不要求等另一条普通命令才能恢复。
- **下令时序已明确**：系统定位猜错后提交调整；助手在联络会话结束后提交调整。两个阶段互斥，网络等待期间保持本阶段暂停，因此没有双方并发下令的竞态，也无需另设“系统先／助手先”的身份排序。后发覆盖自然依照游戏流程中已生效指令的先后。
- **首版范围建议**：只让助手改变灯状态和摄像头朝向／扫描区间，不开放机器人、新增设施或上传报告修改。设施界面显示当前设置和最近一次变更，方便玩家观察系统何时覆盖了方案。

### 4.4 情报真实性与时效性

**用户最新方向**：个人助手不能影响情报的真实性，但可以影响情报的时效。

- **真实性不可变**：已经生成的报告内容、观察时间戳、观察区域和“有人／无人／无法确定”结果不能被助手改写、删除或伪造。系统最终依据游戏程序记录的真实装置状态判定，不接受模型直接提交“无人”或虚假坐标。
- **时效可以改变**：助手可以通过合法设备安排让某区域较晚产生新鲜观察，例如临时关灯、改变摄像头扫描方向。设置持续到被后续有效指令覆盖或受硬规则／RESET限制。报告仍按实际发生时刻记录；没有完成有效检查时只能返回“无法确定”，不能伪装成“无人”。机器人写权限尚未确认，不将延后巡逻作为已定助手能力。
- 为保持统一上报节奏，首版不建议额外实现任意的报告篡改或长时间传输阻塞。把“时效”主要定义为“系统多久能获得该区域的新鲜观测”，由设备运行安排造成，而非修改已生成的数据。若试玩后仍需要更明显的时效操作，再增加“下一批报告延后一批”的单一受限接口。
- 读取边界建议：系统 Agent 可在下一次推理时看到实际设备状态和已到达的报告，但不读取玩家与个人助手的完整对话意图。此处不新增助手读取地图或报告的权限；具体系统可读设备字段待定。

### 4.5 过度依赖的代价：已定联络限制与待验证体验

**用户方向**：以额度用尽体现过度依赖造成的阻碍，可以继续讨论补充削弱；没有采用耗尽即失败或助手故意犯错。

现有资源单位已明确为每点每轮一次会话、每次1–2个改动。一次会话若把有限改动用于本可自行避开的设备，就可能没有剩余改动为同一行动段的维修或撤离创造窗口。离开后不能随时追加命令，系统后发指令也可能改变旧设置，玩家须继续观察和手操。能否在真实关卡中形成这种取舍仍需演练，不能把可能性写成已证实的趣味或平衡。合理咨询、有效节省改动的优秀助手表现应被允许。

通信轮数／内容量控制暂停会话时长；每次1–2个改动限制实际提交，两者不混为一种评分。各点分别拥有机会，不是整轮共享一个1–2次池。局部回退恢复快照中的联络使用状态和现场干预：快照在使用前，可重新会话；快照在使用后，不补一次新会话。全局回退次数不恢复，因此重试次数有限。没有确认额外永久消耗的全局干预额度。

可先复用现有规则产生代价：离开联络点后不能实时追加命令；玩家需到另一个可用点更新描述，或消耗有限回退恢复到某点使用前。行走、等候或维修会推进游戏时间，暂停聊天本身不会推进系统压力。有限会话不能单独证明“依赖必然失败”；最终失败仍来自系统定位命中，不额外加入“求助导致被预测”、隐形惩罚条或随机错误。

## 5. 待调参数与设计建议

| 参数 | 主要影响 |
| --- | --- |
| 定位范围的形状和大小 | 猜测允许多大误差，以及无情报随机猜测的命中率 |
| 上报间隔 Δt | 观察记录等待多久交付，以及每个批次包含多长的观察窗口；不决定设备何时能看见玩家 |
| 每次定位前上报批次数 N | 一次定位前积累多少批情报，以及玩家有多长行动窗口 |
| 检测频率与记录压缩方式 | 如何保留短暂目击与区域变化，同时控制交给模型的记录量；实现参数待定 |
| 灯的关闭数量、持续与冷却 | 能遮断哪些区域、多少次观测，以及何时恢复照明 |
| 装置覆盖、玩家移动与掩体 | 系统能将候选位置缩小到什么程度，历史信息多久过时 |

用户已确认定位形状固定，选项可用方格正方形或近似圆形。具体尺寸以及是否允许系统调整尺寸仍待明确；由游戏固定尺寸、系统只选中心仍是此前建议。任何示例数值只用于推演；当前没有试玩或难度结论。

需检验“每次定位前才关灯”是否成为固定最优，以及历史情报是否足以产生有意义的推断。这些问题通过少量配置推演和灰盒检查；猜错后的新增先复用既有装置类型，不为解决这些问题追加更多装置类型或感知方式。

## 6. 未定的整体玩法

- 已确认修复电机后抵达出口成功；电机数量、具体操作、上报信息粒度、出口可通行反馈及藏身／墙体遮挡继续细化。
- RESET的具体快照字段、双方记忆摘要格式与合法初始化配置。双重RESET、三方记忆保留及联络点使用状态恢复已确认，见第6.2节；会话内通信限制和改动计数细则尚待细化。
- 对话助手相对直接界面的策略价值，过度依赖助手的自然代价。

### 6.1 下一轮优先讨论顺序

1. **感知空间粒度**：已确定方格坐标；进一步明确报告对应单格还是多格区域，以及三种观测如何受墙和灯影响。
2. **双方信息与权限**：个人助手无地图、依靠玩家描述已明确；继续确定非空间接口字段和可改装置，避免接口回执反向暴露地图。
3. **操作与交互限制**：已确定互斥暂停、系统猜错后调度、助手联络结束后提交及后发有效指令覆盖；每点每轮一次，每次1–2个改动，使用标记随快照恢复。继续确定会话内通信限制、改动计数和可改设备字段。

6. **压力、依赖与反馈**：细化猜错后新增设施的类型、槽位、时机与上限；以额度耗尽方向推演依赖代价；定位倒计时、设备变化、猜测范围和依据如何反馈给玩家。

### 6.2 已确认的多轮评价、双重 RESET 与记忆规则

状态：用户以“我同意你的设计”确认上一轮双重RESET框架，明确局部回退后系统和玩家都记得，并进一步要求系统整轮RESET也不能重置个人Agent助手的记忆。以下核心规则作为当前设计基准；具体时间、评分、权限与存储格式继续细化。未实现、未试玩。

#### 核心流程与次数

- **系统RESET**：一轮结算后重新初始化，依据历史摘要调整下一轮合法配置。系统3次轮间RESET与初始轮共同形成4轮评估，前三轮无论成功或最终失败均进入下一轮；第四轮结算后完成整场总评。
- **玩家RESET**：整场共享3次，系统整轮RESET不补满。系统定位命中后，玩家可花一次回退到当前定位行动周期起点；周期指T=N×Δt，而非单次上报间隔Δt。首版只回退一个定位周期，不开放任意n周期选择。
- **失败处理**：玩家选择回退时暂不结算本轮失败；放弃或次数用尽，才记本轮失败并继续下一轮。传感器目击本身仍只产生观察记录。是否允许在定位命中之前主动回退仍待定。
- **全局记录**：双方RESET的使用次数及已经结算的轮次成绩不随局部或整轮重置恢复。

#### 现场恢复与记忆保留

| 内容 | 玩家局部回退 | 系统整轮RESET |
| --- | --- | --- |
| 玩家与装置现场状态 | 恢复本定位周期起点快照 | 按下一轮合法初始配置重建 |
| 玩家已知经验 | 保留 | 保留 |
| 个人Agent助手记忆 | 保留获准观察、对话、干预及复盘经验 | 同样保留，系统无权清除 |
| 系统Agent记忆 | 保留它获准获得的撤销分支历史 | 保留已授权轮末记录及策略摘要 |
| 当前有效报告 | 恢复快照对应的报告状态 | 开始新轮报告序列 |
| 联络点使用状态 | 恢复快照中的已用／未用标记 | 新轮各点重新可用 |
| 全局RESET次数与已结算成绩 | 保留当前账本 | 保留当前账本 |

- **局部快照**：玩家位置、游戏时钟、定位／上报计时、灯状态及冷却、摄像头与机器人运动阶段、电机维修进度及状态、各联络点使用标记、个人临时干预及有效报告一起恢复。具体存储字段待列清。恢复当前周期已保存的设备调度，不因回退额外插入系统定位或调度。
- **历史标记**：被撤销分支的报告和尝试可以保留为记忆，必须注明所属轮次及尝试；不能作为当前分支的新目击。系统不因记忆保留而获得原本无权读取的玩家坐标，个人Agent也不因此获得持续观察或远程追加命令权限。
- **旧策略与新配置**：个人助手记得旧路线与成功方法，但旧设备配置属于历史信息。新轮建议应结合本轮授权数据与玩家新反馈；不能将上一轮摄像头朝向、巡逻路线或冷却直接当作当前状态。
- **记忆与控制分开**：保留“过去执行过某项干预”的记忆不代表该干预继续生效。局部回退按快照恢复现场；整轮RESET清除个人临时干预、重新开放各联络点。历史对话不自动再次提交命令，也不能补满全局RESET次数。一次重新开放的会话仍最多1–2个改动，暂停和通信限制继续适用。
- **回退后的联络**：用户进一步明确，回退后仍须重新到达联络点才能与助手讨论，不在失败位置开放远程会话。保留的旧对话可作为经验，但不能自动生成当前现场信息或追加设备命令；若快照起点恰好位于联络点，具体交互仍沿用联络点规则，不另造离开再返回的惩罚。

#### 待细化与验证

- **适应范围**：沿用一张地图与有限合法配置；新增“猜错后允许增加一处设施”的方向后，不能再默认轮内设备数量固定。个人助手每次联络会话最多1–2个改动；系统仍可调整更多设备，双方按同项有效指令先后覆盖。初始预算、新增上限及整轮RESET如何重建需一起明确，见第6.4节。需验证配置可通关及变化反馈可读；轮末摘要与两个Agent实际可读字段仍待细化，不承诺模型必然有效反制。
- **成绩**：每轮记录修复电机并抵达出口是否成功；用户选择时间、消耗额度等作为后续评分方向，并明确初期暂不细化。被局部回退撤销的命中不直接记本轮失败。具体计时口径、额度类型、权重、优秀阈值及撤销分支统计均留到后续，不把助手对话次数直接等同扣分。
- **10分钟预算**：四轮每轮目标体验约60–90秒，计入联络与推理等待，另为局部回退、介绍和轮间复盘留余量。定位周期10–20秒仅为此前预算示例，未确认或试玩；需以实际模型等待和玩家操作验证整场时长。
- **合作价值**：三方均保留经验，支持复盘与重新规划。个人助手的现场空间认知来自玩家描述；过度依赖以额度耗尽为当前讨论方向，具体策略价值和资源后果仍需关卡推演。旧路线被针对并不专门惩罚使用助手。

### 6.3 已确认的电机任务与上报候选

**已确认**：任务型；加入可维修的电机物件；玩家修完电机并抵达出口即本轮成功；维修也产生上报事件。电机数量、所需修复数量、修复时长及出口具体交互尚未确定。

电机的维修进度属于现场状态，依照既定RESET原则纳入恢复：玩家局部回退恢复快照里的进度与状态；系统整轮RESET恢复该轮初始未修复状态。三方对维修过程的记忆继续保留，不能把完成任务的现场状态与历史经验混为一项。维修进度也随联络／推理暂停而冻结。

以下为本轮助手的简化候选，未获确认：

- **交互**：先按靠近电机、持续交互推进进度推演；建议可中断、离开时保留当次尝试中的已有进度，以支持分段维修与撤离。具体操作键、是否加入额外交互及进度规则未定。
- **规模**：先用一台需要维修的电机与一个出口推演关卡，不据此锁定最终电机数量。
- **事件含义**：优先上报“某台电机在某个实际游戏时刻发生维修活动／完成修复”一类历史事件，沿用已有时间戳与周期批量上报；不默认持续提供玩家当前位置、精确交互点或“现在仍在维修”的实时状态。具体开始／停止／阶段性事件取舍待讨论。
- **信息来源**：维修事件可作为不同于摄像头／机器人的任务遥测来源。建议其是否产生不取决于照明，因此关灯不能自动删除维修上报；照明和扫描干预仍可用于掩护接近、停留及撤离。该独立于照明的规则尚未确认。
- **因果检查**：若在定位边界直接上报“玩家此刻正在固定电机旁维修”，系统可能无需推断就能锁定该处。需要结合实际事件粒度、可中断规则与定位周期推演维修窗口，不能仅靠关灯保证安全，也不必为此增加数值置信度。

下一步优先以联络点—电机—出口构成一轮可演练流程，检验维修驻留、事件产生、系统定位、个人助手干预及撤离之间的关系。初期不展开评分计算。

### 6.4 新增方向：定位未命中后扩大监控

**用户明确方向**：推动玩家的是时间。系统每次周期定位猜错，除了调整既有设施，还允许新增一处设施位置，使玩家之后更难隐藏；具体新增规则继续设计。

与已有规则的关系：设备仍按原节奏感知、上报和定位，新增设施不额外插入猜测。时间压力按游戏内行动时间推进；联络对话和系统推理都暂停，因此输入较慢不额外增加设施。系统定位命中是失败触发点，继续沿用既定局部回退补救与本轮结算区分；本次未另定评分方式。

以下为助手建议与需验证的边界，不视为已定：

- 首版采用预先设计的空设施槽位，系统从合法槽位选择，避免任意坐标生成。新增在本次结算后公示，于下一行动周期开始生效，不以真实玩家坐标替系统选点，也不直接生成在玩家身上造成即时命中。
- 新增灯才会使暗区减少；新增摄像头或机器人只会扩大有照明处的观察覆盖，不能突破暗处无法观察的基准。若核心体验强调暗区收缩，可优先只开放新增灯，摄像头和机器人复用已有配置。
- 需设置槽位／数量上限并检查必要行动窗口。槽位用尽后新增压力会封顶，不能声称能无限递增；是否还需要单轮周期上限留待完整流程验证。
- 系统整轮RESET是否清掉新增设施、局部回退是否恢复新增前快照、系统是否保留未使用新增名额均待定。应与既定现场快照一致，避免回退导致额外免费部署或残留设施；双方记忆保留不代表设施现场保留。
- 区域报告必须保留时间戳。系统掌握设备与地图不等于掌握真实玩家坐标；多设备在不同时刻确认“有人”不能直接作静态区域相交。

当前预赛工作优先是把已定玩法写成清楚的循环图、关卡示意及一次体验演练；具体接口字段与最终布局不作为起草前置。原型阶段再细化可改设备字段、新增设施种类与合法位置，并确定对话轮数、改动计数和时长数值。每点每轮一次、每次1–2个改动、局部回退恢复使用标记已经确定。

同日，v0.16根据用户纠正删除并发竞态与“同刻指令身份排序”的问题。系统行动中调整仅在定位猜错后提交，个人助手调整在联络结束后提交；推理／结算与联络互斥，暂停冻结所有定位计时。双方不会同时下令，后发覆盖按实际阶段先后自然执行。此决定不改变灯时长、冷却、额度和RESET规则。

同日，v0.17记录用户明确的联络资源规则：每个联络点在每个完整RESET轮次只能会话一次；该次会话中个人助手最多提交1–2个改动。多个联络点可分别使用各自额度。回退后是否恢复已经使用的联络点额度尚未决定，不将其擅自写成恢复或不恢复。

同日，v0.18记录用户选择“恢复快照里的使用状态，可以重新会话”：局部回退恢复各联络点使用标记，使用前快照使其重新可用，使用后快照仍记已用；历史对话及三方获准记忆保留，整场3次局部回退计数不恢复。清理v0.17残留的统计单位未定与回退不返还建议，明确每次会话1–2个改动、各点分别计算，不另设永久全局干预账本。预赛表达以玩法框图、示意图与体验演练为主，细化API和最终地图不作为起草前置。
