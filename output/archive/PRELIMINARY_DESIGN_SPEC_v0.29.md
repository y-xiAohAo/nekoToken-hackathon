## 1. 作品目标与边界

Godot；两人 72 小时；目标体验约 10 分钟。高俯角 2.5D，赛博像素三渲二美术。所有可行走格同层，玩家连续实时移动，无跳跃和高低差。方格用于空间描述和范围判定。

用户要求扩大地图，撤销单屏小房间限制。v0.3 先画 36×24 格候选：西南入场、西北分流、东南维修、东北撤离，四区通过带开口的隔墙互通形成环路。区内少量遮挡块留出不同绕行路线；示意使用3个联络点、1台电机、4台摄像头、6盏灯、2台机器人。实机拟跟随角色平移视角，方案图展示全貌；相机方式和具体数量均为提案。

故事沿用团队素材：2042 年，朋友面临永久代理托管，要求玩家本人前往交接塔。原型聚焦途中的自动化检查区，不展开完整城市或多 NPC 支线。

单轮任务：修复电机后抵达出口。维修产生上报事件。电机数量、交互时长和报告粒度在原型中细化；评分按成功情况、用时和消耗方向规划，初期不细化权重。

## 2. 三方职责

| 主体 | 掌握与执行 | 边界 |
| --- | --- | --- |
| 玩家 | 观察设备代号、位置、亮暗及扫描，描述路线，亲自移动和维修 | 手操不能直接调用助手的设备接口 |
| 个人助手 | 通过玩家描述建立空间认知，追问、比较干预方案并提交改动 | 完全无地图与实时画面，只在联络点有效会话；具体非空间可读字段待定 |
| 系统 Agent | 综合授权报告推理当前位置，猜错后调度，整轮 RESET 时调整合法配置 | 不直接读取真实玩家坐标，不因发现就直接判负 |
| 游戏程序 | 实时移动、装置执行、感知、报告、暂停、校验、快照与命中判定 | 模型只在离散节点参与 |

灯、摄像头和机器人没有独立智能。机器人只按指定范围巡逻、以固定视野观察，不追逐或检修。灯每格亮／暗二值，关灯有最大持续时间、冷却和同时关闭数量限制。摄像头首版固定距离、瞬时夹角和扫描速度，优先调整朝向与扫描区间。

## 3. 实时行动、上报与定位

1. 行动期间设备持续检测，发现可发生在任意游戏时刻。
2. 每隔 Δt 批量上报，保留原观察时间戳及当时区域。有人／无人／无法确定分开；有人对应有限区域，不等同真实玩家格。
3. 累计 N 批后暂停，系统依据截至该时刻的授权报告提交一个固定形状的坐标范围。
4. 程序按暂停时冻结的玩家位置判定。命中后可用局部回退；不回退或次数用尽才结算本轮失败。
5. 未命中后，系统可调整既有设备并新增一处设施，再恢复行动。新增种类、合法位置、上限及重置恢复细则未定；预设位置和数量上限是 v0.2 的原型建议。

定位周期 T = N × Δt，不包含暂停等待。N 统计批次，不按设备数或目击事件数计。历史情报需考虑玩家移动，不同时间的有人区域不能简单作静态交集。

## 4. 联络与控制

- 关卡有多个联络点，每个点在每个完整轮次里各一次会话；每次最多 1–2 个改动。具体取 1 还是 2、单个改动的计数边界待原型确定。
- 到达可用点并会话时，所有游戏内运动、感知、上报、灯时长、冷却与定位计时冻结。会话结束后提交合法改动，再从冻结状态恢复。
- 系统只在定位猜错后的暂停阶段调度；个人助手在联络结束后提交。两个阶段互斥，按游戏流程先后执行。
- 同一设施、同一控制项最后一条有效指令覆盖前条，未修改项跨周期保持。灯时长、冷却及 RESET 等硬规则继续生效。
- 助手不能改写、删除或伪造已生成报告、结果、时间戳。可通过未来设备运行影响新鲜观测产生时机。首版拟开放灯与摄像头，不把机器人控制或报告延后 API 写成已确认能力。
- 对话轮数与内容量限制另行细化；外部 Agent 的工具执行额度由游戏接口约束，skill 约定本身不能替代权限。

依赖代价沿用有限联络和有限改动：一次会话若将改动用于能自行绕开的设备，可能失去对同一行动段关键设施的干预机会。离点后不能随时追加。各点分别计算，不另设永久全局干预消耗池；求助或额度耗尽不直接判负。取舍是否有趣仍需试玩。

## 5. 双重 RESET

系统拥有三次轮间整轮 RESET，连同初始轮共四轮。前三轮无论成功还是最终失败都进入下一轮，第四轮后总评。玩家另有整场共享三次局部回退，在定位命中后回到当前定位行动周期起点；不开放任意时间点选择。

| 状态 | 局部回退 | 整轮 RESET |
| --- | --- | --- |
| 玩家、设备、时钟、维修进度及有效报告 | 恢复周期起点快照 | 依下一轮合法配置初始化，开始新报告序列 |
| 联络点已用／未用标记 | 恢复快照状态 | 各点重新可用 |
| 玩家、助手、系统各自获准记忆 | 保留 | 保留 |
| 全局回退次数及已结算成绩 | 不恢复 | 不恢复 |

快照在使用某点之前，回退后该点可重新会话；快照中已经用过，则仍已用。回退后须到达可用联络点才能讨论；若起点就在可用点，不另加离开再返回的要求。旧对话保留为经验，不自动重交撤销分支命令。历史分支不得冒充当前观测，系统也不因保留记忆获得额外真实坐标。

## 6. 预赛表达与原型事项

预赛正文覆盖信息卡、赛题理解、三个设计点、方案价值、72 小时范围和创新点。使用三张框图、V5概念图、方格定位示意和具体行动演练。API 字段、最终坐标和完整 Godot 场景结构不作为起草前置。

地图扩大要与信息粒度和行动距离一起验证：较旧目击之后应有多个可达、未被新报告排除的位置，且单个定位范围不能同时覆盖它们。图中5×5格定位框只作对照，不把正式范围定死。单电机ID足以指明维修位置，不能声称去掉坐标就隐藏位置；事件必须保留真实发生时间，事件粒度仍待定。面积扩大不自动证明定位难度合理。

原型阶段仍需细化：定位区域形状与大小、Δt 与 N、灯时长与冷却、助手合法参数、维修驻留与上报粒度、新增设施规则、对话长度、模型失败后的继续方式。v0.3 的36×24格、三点一电机、设备数量和分阶段排期均为提案；四轮复用同一地图拓扑，只调整合法设备配置。
