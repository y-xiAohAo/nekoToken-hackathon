# 氛围编码

此技能用于需要**确定性工程纪律**的编码任务，而非开放式探索。

此 harness 强制执行：**规格约束 → 检查点审查 → 版本控制回滚 → 自检 → 同行评审**。

## 触发信号

**在以下情况使用 `vibe-coding`：**

- 编码任务具有清晰的规格说明，且定义了边界（必须做 / 严禁做）
- 任务范围可控，代码改动量约二百至五百行
- `git rev-parse --git-dir` 执行成功（项目已初始化版本控制）
- 输出结果需要可维护性，而非仅仅"能跑就行"

**在以下情况不要使用 `vibe-coding`：**

- 任务是无明确边界的开放式探索
- 版本控制未初始化（`NO_GIT`）—— 应拒绝并提示用户执行 `git init`
- 任务是无风险的一行式修改
- 项目明确声明不使用 harness 管控

## 一句话总结

通过自检、自测和同行评审来执行受规格约束的编码任务，**以版本控制作为唯一的回滚机制**。

## 快速工作流程

1. 读取规格说明 + 代码地图 → 向人类复述 → 等待确认
2. 执行 `git status` → 设计 → 实现（约二百至五百行）→ 自测
3. 输出自检报告，附带 `git diff` 摘要
4. 提议更新规格说明 / 代码地图 → 等待人类审批
5. 触发同行评审代理（干净上下文，不携带实现思路）
6. 仅当所有检查点通过后才合并

## 必需产出与检查清单

每个氛围编码任务必须产出以下产物：

| 产物 | 位置 | 用途 |
|------|------|------|
| 规格切片 | 来自 `.kimi/vibe_specs/[模块]-spec.md` | 边界定义 |
| 任务包 | 由人类分配的任务切片 | 执行单元 |
| 自检报告 | 内嵌输出或 `.kimi/vibe_specs/self-checks/T-XXX.md` | 正确性证据 |
| 同行评审报告 | 通过代理工具触发 | 独立验证 |
| 版本控制差异 | `git diff --cached` | 变更审查材料 |

## 控制工作流程

### 步骤一：版本控制准入检查（强制）

```bash
git rev-parse --git-dir 2>/dev/null || echo "NO_GIT"
```

- `NO_GIT` → **拒绝开工**，报告："请执行 `git init`"
- 无远程仓库 → **允许开工**，但在规格说明中记录 `[警告] 未配置远程仓库`

### 步骤二：加载上下文

按顺序读取：
1. `.kimi/vibe_specs/README.md` — 规格说明索引
2. `[模块]-spec.md` — 模块规格说明
3. `CODEMAP.md` — 代码地形

### 步骤三：检查点一 — 复述确认

向人类复述："本任务包的目标、边界、验收标准"。等待 `放行` 或 `纠正`。

### 步骤四：实现

- 执行 `git status` 确认工作区干净
- 设计 → 编码 → 自测（pytest / vitest / eslint）
- **严禁**超出"必须做"列表的范围

### 步骤五：检查点二 — 自检报告

必须包含：
- 改动清单（文件 + 理由）
- `git diff --stat` 输出
- 验证命令与结果
- 风险与排查建议

### 步骤六：检查点三 — 规格说明 / 代码地图更新

代理撰写"更新建议" → 上报人类 → 人类审批后代理由修改文件 → 再次确认。

### 步骤七：检查点四 — 同行评审

触发同行评审代理：
- 提示词中**仅提供**规格说明 + 代码路径
- **不提供**主代理的实现思路、已知变通方案、中间推理
- 同行评审代理输出审查报告（通过 / 不通过 + 意见）

### 步骤八：合并

人类审批同行评审报告 → 放行 → `git commit` → 持续集成 / 持续部署回归。

## 禁止事项 / 陷阱

- **严禁**不读规格说明就直接写代码
- **严禁**使用文件备份（`.kimi/backups/`）替代版本控制进行回滚
- **严禁**跳过自检报告
- **严禁**让同行评审代理看到实现思路
- **严禁**修改任务板（任务索引 / 任务状态）
- **严禁**超出任务包"必须做"列表的范围
- **严禁**未经检查点四的人类审批就直接提交

## 新会话接续

当上下文腐烂时（超过五十轮对话 / 与规格说明矛盾 / 重复已确认的事实）：

1. 执行 `git status`（或暂存）
2. 执行 `/clear` 或新开终端会话
3. 重新加载：索引 → 规格说明 → 代码地图
4. 在向人类复述规格说明后，再发放下一个任务包
